#### 기획 배경

HONDI가 제주 혼자 여행 커뮤니티를 표방하는 만큼, 제주의 대표 도보 콘텐츠인 **올레길** 정보 조회 기능 추가. 백엔드 API 없이 프론트 정적 데이터로만 운영하는 방식을 선택했다.

**이유:**
- 올레길 26개 코스 데이터는 고정값 (공공 도메인) → DB 필요 없음
- 카카오맵 폴리라인 시각화 → 기존 `KakaoMap` 컴포넌트 확장으로 구현 가능
- 목록 필터 + 상세 지도 구조 → 포트폴리오에서 서비스 완결성 어필

#### 1. 정적 데이터 (`olleTrails.js`)

**코스 구성:** 메인 21코스 + 분기 5코스(1-1, 7-1, 10-1, 14-1, 18-1) = **총 26개**

```js
// 각 코스 객체 스키마
{
  id: Number,                   // 라우트 파라미터
  name: String,                 // "1코스", "1-1코스"
  subtitle: String,             // "시흥초등학교 → 광치기해변"
  region: "제주시" | "서귀포시",
  distance: Number,             // km
  difficulty: "하" | "중" | "상",
  duration: String,             // "4~5시간"
  terrain: String,              // "해안·오름"
  description: String,
  startPoint: { name, lat, lng },
  endPoint:   { name, lat, lng },
  stamps: String[],             // 스탬프 포인트 (4~5개)
  path: { lat, lng }[],         // 폴리라인 좌표 (5~9개)
}
```

**좌표 전략:**
공식 GPS 트랙은 포인트가 수백~수천 개라 그대로 쓰면 지도 렌더 성능에 부담. 코스당 **핵심 거점 5~9개**만 사용해 방향감은 살리되 세밀한 굴곡은 생략.

원형 코스(우도·가파도·추자도)는 `path` 배열의 첫 좌표 = 마지막 좌표로 설정해 폐합 경로 표현.

#### 기획 배경

날씨 위젯이 현재 시각 기온·날씨 상태만 보여주고 있어, "오늘 날씨는 알겠는데 내일·모레는?" 이라는 질문에 답을 못 했다. 기상청 API가 이미 연결돼 있으니, **단기예보 API(getVilageFcst)**를 추가 호출해 3일 예보를 탭으로 노출하는 방향으로 개선.

#### 백엔드 — WeatherService.java

기존에는 `getUltraSrtFcst`(초단기예보)만 호출하고 있었다. `getVilageFcst`(단기예보) 호출을 위한 `getForecast(city)` 메서드를 추가.

**base_time 계산:**

단기예보는 0200, 0500, 0800, 1100, 1400, 1700, 2000, 2300시에 발표되고, 발표 10분 후 조회 가능. 현재 시각 기준으로 가장 최근 발표 시각을 역순으로 탐색.

```java
private static final int[] FCST_BASE_HOURS = {2, 5, 8, 11, 14, 17, 20, 23};

// 발표 시각 + 10분 이상 지난 가장 최근 시각 선택
int curTotalMin = now.getHour() * 60 + now.getMinute();
for (int i = FCST_BASE_HOURS.length - 1; i >= 0; i--) {
    if (curTotalMin >= FCST_BASE_HOURS[i] * 60 + 10) {
        baseDateTime = now.withHour(FCST_BASE_HOURS[i])...;
        break;
    }
}
// 00시~02시10분 구간: 전날 23시 발표분 사용
```

**데이터 파싱 전략:**

단기예보는 시간별 카테고리가 12~14개 × 72시간 분량으로 응답. numOfRows=1000으로 한 번에 수신.

| 카테고리 | 처리 방식 |
|----------|----------|
| `TMN` (일 최저기온) | 날짜별 첫 출현값 사용 |
| `TMX` (일 최고기온) | 날짜별 첫 출현값 사용 |
| `TMP` (시간별 기온) | TMN/TMX 없을 때 min/max로 fallback |
| `SKY` (하늘상태) | 1200 → 1500 → 1300 → 첫값 우선순위 |
| `PTY` (강수형태) | 동일 |

낮 시간대(12시) 값을 대표값으로 쓰는 이유: 사용자 입장에서 "내일 날씨"를 판단할 때 낮 날씨가 가장 직관적이기 때문. 새벽 3시 흐림과 낮 12시 맑음이 같은 날이면, "맑음"으로 보여주는 게 자연스럽다.

```java
private int pickRepresentativeValue(Map<String, String> timeMap) {
    for (String t : new String[]{"1200", "1500", "1300", "1100", "0900"}) {
        if (timeMap.containsKey(t)) return parseInt(timeMap.get(t));
    }
    return parseInt(timeMap.values().iterator().next());
}
```

반환 구조: `List<Map>` — 오늘/내일/모레 3개 항목, 각 항목은 `date`, `label`, `sky`, `ptyCode`, `tmin`, `tmax` 포함.

```ts
export interface ForecastDay {
  date: string;
  label: string;       // "오늘" | "내일" | "모레"

  tmin: number;
  tmax: number;

  const response = await axiosApi.get("/api/weather/forecast", { params: { city } });
  return response.data;
```

#### 프론트엔드 — WeatherSection.jsx

**추가된 상태 및 쿼리:**

```js
const [mode, setMode] = useState('current'); // 'current' | 'forecast'

const { data: forecastData, isLoading: forecastLoading } = useQuery({
  queryKey: ['jejuForecast', city],
  queryFn: () => getJejuForecast(city),
  staleTime: 60 * 60 * 1000, // 1시간 (날씨 예보는 매시간 갱신)
```

`enabled: mode === 'forecast'` 처리 이유: 사용자가 [예보] 탭을 누르기 전에는 API를 호출하지 않음. 위젯을 열었다고 자동으로 예보까지 불러오면 불필요한 API 요청이 발생한다.
