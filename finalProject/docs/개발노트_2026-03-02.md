### [Feat] 올레길 지도 경로 개선 — 바다를 가로지르는 직선 문제 해결

---

#### 기획 배경

올레길 상세 페이지(`OlleDetail.jsx`)에는 카카오 맵으로 코스 경로를 그려주는 기능이 있다.

그런데 실제로 지도를 열어보면 경로선이 **바다 한가운데를 가로질러** 표시되는 문제가 있었다.

특히 1코스가 심했다. 시흥초등학교(출발)와 광치기해변(도착)은 직선 거리로 약 2km 정도인데, 실제 올레길은 성산 반도를 빙 돌아가는 15.1km 코스다. 기존 구현에서는 이 두 점 사이를 직선으로 이어버리니 선이 바다를 통과했다.

---

#### 원인 분석

`olleTrails.js`는 각 코스의 경로를 `path: [{lat, lng}, ...]` 배열로 정의하고,
`KakaoMap.jsx`에서 이 배열을 카카오 지도 `Polyline`의 `path` prop으로 전달한다.

Polyline은 점들을 **직선으로** 이어준다. 점이 충분히 촘촘하면 실제 길처럼 보이지만,
점이 드문드문하면 직선이 지형을 무시하고 바다나 산을 그대로 관통한다.

**기존 olleTrails.js:** 코스당 약 7개 좌표
**문제:** 7개 점을 직선으로 이으면 해안선을 따라가지 않고 바다를 가로지름

---

#### 해결 방법

모든 26개 코스의 좌표를 **18~22개**로 늘려서, 실제 해안선/지형을 따라가도록 수정.

좌표 수를 늘리는 것만으로 직선 구간이 짧아지고, 짧은 직선들이 모이면 곡선처럼 보인다.

### [Feat] 올레길 경로 좌표 전면 재작성 — 선형보간 문제 해결

---

#### 문제 재발 — 1차 수정 후에도 직선이 그대로

1차 수정(좌표 수 7개 → 18~22개) 직후, 실제 지도에서 확인해보니 경로선이 **여전히 직선**이었다.

11코스(모슬포항 → 무릉외갓집) 등에서 두 마커 사이를 직선으로 가로지르는 선이 그대로 표시됐다.

---

#### 진짜 원인 — 선형보간(Linear Interpolation)

1차 수정 때 좌표를 늘리는 방법으로 A(출발)와 B(도착) 사이를 균등하게 나눠 삽입했다.

이렇게 하면 점이 아무리 많아도 **모든 점이 A-B 직선 위에 있다**. 수학적으로 완전히 일직선.

Polyline은 이 점들을 직선으로 이으므로 **결과도 A-B 직선과 동일**하게 보인다.

```
선형보간 예시 (5개 점):
A ─── p1 ─── p2 ─── p3 ─── B
             ↕
   모두 A-B 직선 위에 있음 → 직선과 구분 불가
```

---

#### 해결 방법 — 지형을 반영한 방향 전환 좌표

경로가 실제처럼 보이려면 A-B 직선에서 **의미 있게 벗어나는 구간**이 필요하다.

즉, "북쪽으로 갔다가 내려오는" U자, "서쪽으로 훅 돌아오는" 훅 모양처럼, 중간에 방향이 바뀌는 지점을 실제 제주 지형 기반으로 지정해야 한다.

**원칙:**
- 각 코스의 핵심 지리 랜드마크(해안선 꺾임, 포구, 오름 등)를 반환점으로 설정
- 해당 지점이 출발-도착 직선에서 충분히 이탈하도록 좌표 배치
- 짧은 직선들이 모여 실제 경로 형태를 이루도록 구성

### [Feat] 올레길 경로 — OSM 실측 GPS 데이터 적용

---

#### 기획 배경

2차 수정(지형 기반 좌표 재작성)으로 직선 문제를 해결했지만, 여전히 좌표는 수동으로 작성한 근사값이었다. 실제 트레킹 경로와 다소 차이가 있었고, 특히 1코스처럼 해안선이 복잡한 구간에서는 눈에 띄게 부정확했다.

"네비게이션처럼 실제 길을 따라 표시할 수 없냐"는 요구에 따라, OpenStreetMap(OSM)에 등록된 **실측 GPS 트레킹 데이터**를 수집해 반영하기로 했다.

---

#### 구현 방법

**1단계 — Overpass API로 GPS 좌표 수집**

OSM Overpass API를 통해 제주 올레길 route relation을 쿼리하고, 각 way의 GPS 좌표를 수집한다.

```js
// scripts/fetchOlleOsm.cjs
const result = await overpassQuery(
  `[out:json][timeout:90];relation(${relId});out geom;`
);
```

쿼리 결과로 받은 relation의 way 멤버들을 **체이닝**해 연속된 경로를 구성한다. OSM relation 안의 way들은 정렬이 보장되지 않으므로, 각 way의 끝점 거리를 비교해 순방향/역방향을 자동 판별한다.

```js
// 끝점 거리 비교로 forward/reverse 결정
if (dist(last, geo[0]) <= dist(last, geo[geo.length - 1])) {
  result.push(...geo.slice(1));       // 순방향
} else {
  result.push(...[...geo].reverse().slice(1)); // 역방향
}
```

**2단계 — Douglas-Peucker 알고리즘으로 다운샘플링**

원본 GPS 데이터는 수천 개의 점을 포함한다. 웹 렌더링 성능을 위해 Douglas-Peucker 알고리즘으로 좌표를 줄이되 경로의 형태는 유지한다 (epsilon=0.00015, 약 15m 정밀도).

```js
function douglasPeucker(pts, eps) {
  // 직선에서 가장 멀리 벗어난 점 기준으로 재귀 분할
  // epsilon 이하 이탈은 무시 → 압축
}
```

**3단계 — olleTrails.js path 블록 교체**

applyOsmPaths.cjs가 `osmPaths.json` → `olleTrails.js`의 `path: [...]` 블록을 텍스트 치환 방식으로 교체한다. 전체 파일을 재직렬화하지 않고 해당 블록만 regex로 찾아 교체하므로, 다른 필드(description, stamps 등)에 영향이 없다.

```js
const idPattern = new RegExp(
  `(\\bid\\s*:\\s*${appId}\\b[\\s\\S]*?)path\\s*:\\s*\\[([\\s\\S]*?)\\](?=\\s*[,}])`, ''
);
src = src.replace(idPattern, `$1${newPathBlock}`);
```

### [Design] 자유게시판 목록/상세 UI 전면 개선

---

#### 기획 배경

기존 자유게시판은 기능은 동작하지만 디자인이 단조롭고 가독성이 낮았다. 게시판 목록은 단순 나열, 상세 페이지는 댓글/대댓글 구분이 불명확했다.

포트폴리오 완성도를 위해 목록과 상세 모두 UI를 전면 개선했다.

---

#### 목록 페이지 (Freeboards.jsx)

**HOT 게시글 시각화**

좋아요 5개 이상 또는 댓글 10개 이상이면 번호 대신 Flame 아이콘 뱃지를 표시하고, 행 hover 색상도 orange 계열로 전환한다.

```jsx
const isHot = board.likeCount >= 5 || board.commentCount >= 10;
// 번호 컬럼
{isHot ? (
  <span className="inline-flex items-center justify-center w-7 h-7 bg-gradient-to-br from-orange-400 to-red-400 rounded-lg">
    <Flame className="w-3.5 h-3.5 text-white" />
  </span>
) : (
  <span className="text-sm text-slate-300 font-medium">{num}</span>
)}
```

**기타 개선**

- 히어로 배너 480px → 360px (본문 집중)
- 총 게시글 수 + 현재 페이지 헤더 표시
- 댓글 수 `[N]` 인라인 표시 (네이버 게시판 스타일)
- 좋아요 있는 글은 통계 rose 색상으로 강조
- 검색창 X 버튼으로 즉시 초기화

#### 상세 페이지 (FreeboardDetail.jsx)

**댓글/대댓글 시각적 구분**

- 댓글: `bg-slate-50 rounded-2xl` 버블 스타일
- 대댓글: `bg-sky-50/60 border border-sky-100/60` + CornerDownRight 아이콘으로 들여쓰기 표현

**Avatar 컴포넌트 분리**

작성자 프로필 이미지를 재사용 가능한 `Avatar` 컴포넌트로 분리. `size` prop으로 `md` / `sm` 크기 조절.

```jsx
function Avatar({ src, name, size = 'md' }) {
  const sz = size === 'sm'
    ? 'w-8 h-8 text-xs rounded-xl'
    : 'w-11 h-11 text-sm rounded-2xl';
  return (
    <div className={`${sz} bg-gradient-to-br from-sky-400 to-cyan-400 ...`}>
      {src ? <img src={src} ... /> : name?.[0] || '?'}
    </div>
  );
}
```

**기타 개선**

- 본문 텍스트 `text-sm` → `text-[15px] leading-8` (가독성 향상)
- 신고 모달 옵션 2열 그리드 레이아웃

### [Design] 올레길 코스 소개 섹션 가독성 개선

---

#### 기획 배경

OlleDetail 페이지의 "코스 소개" 섹션이 단순 `text-sm` 단락 하나로 표시되어 가독성이 낮고 시각적으로 밋밋했다.

---

#### 변경 내용

**문장 단락 분리**

설명 문자열을 `.`, `!`, `?` 기준으로 문장 단위로 분리해 각각 `<p>` 태그로 렌더링한다. 한 덩어리의 긴 텍스트가 문장별로 구분되어 읽기 쉬워진다.

```jsx
{(trail.description.match(/[^.!?]+[.!?]+/g) ?? [trail.description])
  .map((s) => s.trim())
  .filter(Boolean)
  .map((sentence, i) => (
    <p key={i} className={`text-[15px] leading-8 ${
      i === 0 ? 'font-semibold text-slate-800' : 'text-slate-600'
    }`}>
      {sentence}
    </p>
  ))}
```

**첫 문장 도입부 강조**

첫 번째 문장(예: "제주 올레의 시작점.")을 `font-semibold text-slate-800`으로 굵게 표시해 코스의 핵심 키워드를 한눈에 파악할 수 있게 했다.

**섹션 헤더 개선**

- Flag 아이콘 → 그라데이션(teal→emerald) 배경 아이콘 박스로 교체
- 제목 `text-sm` → `text-base font-bold`
- 설명 박스에 연한 teal/emerald 그라데이션 배경 + 장식용 큰 따옴표(") 추가
