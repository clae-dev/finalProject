### [Feat] 올레길 지도 경로 개선 — 바다를 가로지르는 직선 문제 해결

---

#### 기획 배경

올레길 상세 페이지(`OlleDetail.jsx`)에는 카카오 맵으로 코스 경로를 그려주는 기능이 있다.

그런데 실제로 지도를 열어보면 경로선이 **바다 한가운데를 가로질러** 표시되는 문제가 있었다.

특히 1코스가 심했다. 시흥초등학교(출발)와 광치기해변(도착)은 직선 거리로 약 2km 정도인데, 실제 올레길은 성산 반도를 빙 돌아가는 15.1km 코스다. 기존 구현에서는 이 두 점 사이를 직선으로 이어버리니 선이 바다를 통과했다.

---

#### 원인 분석

`olleTrails.js`는 각 코스의 경로를 `path: [{lat, lng}, ...]` 배열로 정의하고,
`KakaoMap.jsx`에서 이 배열을 카카오 지도 `Polyline`의 `path` prop으로 전달한다.

Polyline은 점들을 **직선으로** 이어준다. 점이 충분히 촘촘하면 실제 길처럼 보이지만,
점이 드문드문하면 직선이 지형을 무시하고 바다나 산을 그대로 관통한다.

**기존 olleTrails.js:** 코스당 약 7개 좌표
**문제:** 7개 점을 직선으로 이으면 해안선을 따라가지 않고 바다를 가로지름

---

#### 해결 방법

모든 26개 코스의 좌표를 **18~22개**로 늘려서, 실제 해안선/지형을 따라가도록 수정.

좌표 수를 늘리는 것만으로 직선 구간이 짧아지고, 짧은 직선들이 모이면 곡선처럼 보인다.

---

#### 1코스 — 핵심 수정 사례

1코스가 가장 잘못 표시되고 있었다.

| 항목 | 내용 |
|------|------|
| 출발 | 시흥초등학교 (33.4679, 126.9302) |
| 도착 | 광치기해변 (33.4557, 126.9215) |
| 실제 거리 | 15.1 km |
| 직선 거리 | 약 2 km |

**기존 경로의 문제:**
출발점에서 도착점 방향(남서쪽)으로 직선이 이어지는데, 그 사이에 바다가 있다.

**실제 올레길 1코스 루트:**
시흥에서 출발 → **북쪽으로** 성산 반도의 동쪽 해안을 따라 올라감 → 오조리 최북단 → 다시 **남쪽으로** 내려와 광치기해변 도착

```
        오조리 (최북단)
           ↑    ↓
    ←북상  |    |  남하↓
           |    |
시흥 → → →      → → → 광치기해변
(출발)                  (도착)
```

#### 기술 구조

```
olleTrails.js (정적 데이터)
    ↓  path 배열 전달
OlleDetail.jsx (코스 선택 → selectedTrail.path)
    ↓  path prop
KakaoMap.jsx (Polyline path={path} strokeColor="#3B82F6")
```

API 코드나 컴포넌트 로직은 건드리지 않고, **좌표 데이터만 보강**하는 방식으로 해결했다.

### [Feat] 올레길 경로 좌표 전면 재작성 — 선형보간 문제 해결

---

#### 문제 재발 — 1차 수정 후에도 직선이 그대로

1차 수정(좌표 수 7개 → 18~22개) 직후, 실제 지도에서 확인해보니 경로선이 **여전히 직선**이었다.

11코스(모슬포항 → 무릉외갓집) 등에서 두 마커 사이를 직선으로 가로지르는 선이 그대로 표시됐다.

---

#### 진짜 원인 — 선형보간(Linear Interpolation)

1차 수정 때 좌표를 늘리는 방법으로 A(출발)와 B(도착) 사이를 균등하게 나눠 삽입했다.

이렇게 하면 점이 아무리 많아도 **모든 점이 A-B 직선 위에 있다**. 수학적으로 완전히 일직선.

Polyline은 이 점들을 직선으로 이으므로 **결과도 A-B 직선과 동일**하게 보인다.

```
선형보간 예시 (5개 점):
A ─── p1 ─── p2 ─── p3 ─── B
             ↕
   모두 A-B 직선 위에 있음 → 직선과 구분 불가
```

---

#### 해결 방법 — 지형을 반영한 방향 전환 좌표

경로가 실제처럼 보이려면 A-B 직선에서 **의미 있게 벗어나는 구간**이 필요하다.

즉, "북쪽으로 갔다가 내려오는" U자, "서쪽으로 훅 돌아오는" 훅 모양처럼, 중간에 방향이 바뀌는 지점을 실제 제주 지형 기반으로 지정해야 한다.

**원칙:**
- 각 코스의 핵심 지리 랜드마크(해안선 꺾임, 포구, 오름 등)를 반환점으로 설정
- 해당 지점이 출발-도착 직선에서 충분히 이탈하도록 좌표 배치
- 짧은 직선들이 모여 실제 경로 형태를 이루도록 구성

#### 주요 코스별 수정 내용

**9코스 (대평 → 화순)** — 용머리해안 서쪽 훅

실제 경로는 화순보다 훨씬 서쪽의 용머리해안까지 갔다가 되돌아온다.

```
대평(출발) → 서쪽 → 용머리해안(lng 126.3278) → 동쪽 → 화순(도착, lng 126.3530)
```

용머리해안이 화순보다 더 서쪽에 위치하기 때문에, 직선(대평→화순)에서 서쪽으로 크게 이탈한다.

---

**10코스 (화순 → 모슬포)** — 사계·송악산 최남단 경유

```
화순(출발) → 남하 → 사계리 → 송악산 최남단(lat 33.2022, 제주 남단) → 북상 → 모슬포항(도착)
```

출발지보다 훨씬 남쪽(lat 33.2022)까지 내려갔다가 올라오는 구조라 U자형 경로가 자연스럽게 표현된다.

---

**11코스 (모슬포 → 무릉)** — 모슬포 시내 동쪽 우회

```
모슬포항(출발) → 동쪽으로 시내 통과(lng 126.2648) → 추사관 → 대정읍 → 무릉(도착, lng 126.2220)
```

출발점(lng 126.2600)보다 더 동쪽으로 갔다가 서북쪽으로 빠지므로 직선과 다른 경로가 표현된다.

---

**4코스 (표선 → 남원)** — 가시리·따라비오름 북쪽 우회

```
표선(출발, lat 33.3730) → 북상 → 가시리(lat 33.3855, 가장 북쪽) → 남하 → 남원(도착, lat 33.2780)
```

출발보다 더 북쪽으로 올라갔다가 남원까지 크게 내려오는 형태.

---

**12코스 (무릉 → 용수)** — 신도포구 서쪽 경유 후 북상

```
무릉(출발) → 서쪽 해안(신도포구, lng 126.1920, 가장 서쪽) → 북쪽으로 해안 따라 → 용수포구(도착)
```

제주 서쪽 해안선의 실제 꺾임을 반영해 서쪽 훅 이후 북상하는 형태.

---

**7코스 (외돌개 → 월평)** — 중문색달해변 서쪽 훅

```
외돌개(출발, lng 126.5470) → 서쪽 → 중문색달(lng 126.4448, 가장 서쪽) → 동쪽 → 월평(도착, lng 126.4970)
```

출발지보다 더 서쪽으로 갔다가 중간 지점(월평)으로 돌아오는 구조.
