### [Feat] AI 창식이 대화 기록 localStorage 저장

**파일:** `src/components/ai/AiChatPanel.jsx`

---

#### 기획 배경

AI 창식이와 대화를 나누다가 페이지를 새로고침하거나 다른 페이지로 이동했다가 돌아오면 대화 내용이 초기화되는 문제가 있었다. 챗봇 특성상 이전 맥락이 유지되는 것이 자연스러운 UX이고, 포트폴리오 관점에서도 "대화 지속성"은 완성도에 직결되는 요소라 개선을 결정.

---

#### 구현 내용

**변경 전:**

```js
const [messages, setMessages] = useState([WELCOME_MESSAGE]);
```

초기값이 항상 WELCOME_MESSAGE 하나짜리 배열 → 마운트마다 리셋.

**변경 후:**

```js
const STORAGE_KEY = 'changsik_chat_history';

function loadMessages() {
  try {
    const saved = localStorage.getItem(STORAGE_KEY);
    if (saved) {
      const parsed = JSON.parse(saved);
      if (Array.isArray(parsed) && parsed.length > 0) return parsed;
    }
  } catch {
    // 파싱 실패 시 무시
  }
  return [WELCOME_MESSAGE];
}

const [messages, setMessages] = useState(loadMessages);
```

`useState`에 초기값이 아닌 **초기화 함수(initializer function)**를 전달하는 패턴 사용.

> `useState(loadMessages)` vs `useState(loadMessages())`
> - 함수 참조를 넘기면 React가 **최초 마운트 시 한 번만** 호출
> - 괄호를 붙여 호출 결과를 넘기면 **렌더마다** 실행됨
> → 전자가 올바른 패턴. localStorage 접근 비용을 최초 마운트에만 지불.

---

**저장 useEffect 추가:**

```js
useEffect(() => {
  try {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(messages));
  } catch {
    // 저장 실패 시 무시 (용량 초과 등)
  }
}, [messages]);
```

`messages`가 바뀔 때마다 직렬화해서 저장. `try/catch`로 감싼 이유는 localStorage 용량 초과(`QuotaExceededError`) 시 앱이 크래시되지 않도록 방어하기 위함.

---

**초기화(↺) 버튼 연동:**

```js
const handleReset = () => {
  setMessages([WELCOME_MESSAGE]);
  setError(null);
  setInputValue('');
  localStorage.removeItem(STORAGE_KEY);  // 추가
};
```

state 리셋과 동시에 localStorage도 삭제. 삭제하지 않으면 다음 마운트 시 `loadMessages`가 웰컴 메시지 대신 이전 내용을 다시 복원해버리는 문제가 생김.

---

#### 동작 흐름

```
첫 방문
  └── loadMessages() → localStorage 없음 → [WELCOME_MESSAGE] 반환

대화 진행
  └── messages 변경 → useEffect → localStorage.setItem (자동 저장)

새로고침 / 재방문
  └── loadMessages() → localStorage 있음 → JSON.parse → 이전 대화 배열 반환
  └── 이전 대화 그대로 복원됨

초기화 버튼 클릭
  └── setMessages([WELCOME_MESSAGE]) + localStorage.removeItem
  └── 다음 마운트 시 다시 웰컴 메시지로 시작
```

---

#### 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| localStorage 미지원 브라우저 | `try/catch` → 웰컴 메시지로 fallback |
| 저장 데이터 파싱 오류 (손상) | `try/catch` → 웰컴 메시지로 fallback |
| localStorage 용량 초과 | `try/catch` → 저장 실패 무시, 기존 대화는 유지 |
| 빈 배열 저장된 경우 | `Array.isArray && length > 0` 조건 → 웰컴 메시지로 fallback |

### [Feat] 동행 D-day 임박 색상 강조

**파일:** `src/pages/companion/Companions.jsx`

---

#### 기획 배경

`getDday()` 함수와 카드 이미지 위 D-day 배지는 이미 구현되어 있었으나, 모든 날짜가 동일한 흰 배경 + 하늘색 텍스트로 표시됐다. D-1과 D-30이 같은 색이면 긴박감 전달이 안 된다. 동행 모집의 특성상 마감 임박을 시각적으로 강조하면 참여 유도에도 효과적.

---

#### 구현 내용

`getDdayStyle(dday)` 헬퍼 함수를 추가하고, 배지 className을 동적으로 적용하는 방식으로 변경.

**변경 전:**

```jsx
{dday && (
  <span className="absolute top-4 right-4 px-3.5 py-1.5 bg-white/95 backdrop-blur-sm rounded-full text-xs font-bold text-sky-500 shadow-lg">
    {dday}
  </span>
)}
```

**변경 후:**

```js
function getDdayStyle(dday) {
  if (dday === 'D-Day') {
    return 'bg-orange-500 text-white shadow-orange-300/60 animate-pulse';
  }
  const n = parseInt(dday.replace('D-', ''), 10);
  if (n <= 3)  return 'bg-red-500 text-white shadow-red-300/60';
  if (n <= 7)  return 'bg-amber-400 text-white shadow-amber-300/60';
  return 'bg-white/95 text-sky-500 shadow-sky-100/60';
}
```

```jsx
{dday && (
  <span className={`absolute top-4 right-4 px-3.5 py-1.5 backdrop-blur-sm rounded-full text-xs font-bold shadow-lg ${getDdayStyle(dday)}`}>
    {dday}
  </span>
)}
```

---

#### 색상 기준

| D-day 값 | 배경색 | 의도 |
|-----------|--------|------|
| `D-Day` | 주황 (`orange-500`) + `animate-pulse` | 오늘이 여행 당일, 최우선 강조 |
| `D-1` ~ `D-3` | 빨강 (`red-500`) | 3일 이내 임박, 긴박감 |
| `D-4` ~ `D-7` | 노랑 (`amber-400`) | 1주일 내, 경고 수준 |
| `D-8` 이상 | 흰 배경 + 하늘색 (`sky-500`) | 여유 있음, 기존 스타일 유지 |

기준값 설정 근거:
- **D-3**: 비행기·숙소 예약 취소 위약금이 주로 3일 전부터 발생 → 사용자 입장에서 "결정해야 할" 데드라인
- **D-7**: 일반적으로 여행 준비(짐 챙기기 등)를 1주일 전부터 시작 → 서두를 필요가 있는 시점
- `animate-pulse`: Tailwind CSS 내장 애니메이션. 배지가 주기적으로 투명도 변화 → 당일 게시글이 시각적으로 튀어 보임

### [Perf] HeroSection LCP 이미지 우선순위 지정

**파일:** `src/components/main/HeroSection.jsx`

**문제:**

히어로 슬라이드 이미지 3장이 전부 동일 속성으로 처리됨.

- 첫 번째 이미지: 페이지 로드 시 바로 보이는 **LCP(Largest Contentful Paint)** 대상 — 브라우저가 우선 다운로드해야 하지만 힌트가 없음
- 두·세 번째 이미지: 5초 후에야 표시되는데 즉시 다운로드됨 → 첫 번째 이미지 로딩을 방해

**수정:**

```jsx
// 변경 전
<img src={slide.image} alt="" className="..." />

// 변경 후
<img
  src={slide.image}
  alt=""
  className="..."
  loading={idx === 0 ? 'eager' : 'lazy'}
  fetchpriority={idx === 0 ? 'high' : 'low'}
/>
```

| 속성 | idx === 0 (첫 슬라이드) | idx > 0 (나머지) |
|------|------------------------|-----------------|
| `loading` | `eager` | `lazy` |
| `fetchpriority` | `high` | `low` |

- `fetchpriority="high"`: 브라우저 리소스 우선순위 힌트. 다른 이미지보다 먼저 요청.
- `loading="lazy"`: 두·세 번째 이미지는 뷰포트 진입 시점까지 다운로드 지연.
