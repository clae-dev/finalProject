- `Date.now() - lastActivity > 30분` 이면 Refresh Token 유효 여부와 무관하게 즉시 로그아웃
- `INACTIVITY_LIMIT` 상수 중복 선언 제거

### 1. 코드 스플리팅 (React.lazy + Suspense)

**적용 파일:** `src/App.jsx`

**원리:**
`React.lazy()`로 감싼 컴포넌트는 실제로 해당 라우트에 진입하는 순간 네트워크 요청을 보내서 JS 청크를 받아온다. 첫 로딩 시에는 포함되지 않음.

**변경 전:**
```js
import Accommodations from './pages/accommodation/Accommodations';
import AdminPage from './pages/admin/AdminPage';
// ... 25개 더
```

**변경 후:**
```js
import { lazy, Suspense } from 'react';

const Accommodations = lazy(() => import('./pages/accommodation/Accommodations'));
const AdminPage = lazy(() => import('./pages/admin/AdminPage'));
// ... 25개 더
```

라우터를 `<Suspense fallback={null}>` 로 감싸 로딩 중에는 아무것도 보여주지 않음 (기존 PageTransition 애니메이션과 충돌 방지).

**적용 제외 항목:**
- `WeatherWidget`, `ChatBubble`, `AiChatBubble` — 모든 페이지에서 항상 표시되므로 lazy 불필요
- `AuthProvider`, `PageTransition` — 라우팅 인프라 코드

**효과:**
초기 로드 시 `index.js` 136 KB (gzip: 44 KB) 만 받으면 됨. 나머지는 라우트 진입 시 on-demand 로드.

### 2. Vite 벤더 청크 분리 (manualChunks)

**적용 파일:** `vite.config.ts`

**원리:**
서드파티 라이브러리는 소스코드와 달리 버전이 바뀌지 않으면 내용이 변하지 않음.
분리해두면 브라우저 캐시를 더 오래 활용할 수 있고, 소스코드 변경이 라이브러리 청크 해시에 영향을 주지 않음.

**분리 기준:**

| 청크명 | 포함 라이브러리 | 크기 (gzip) |
|--------|----------------|-------------|
| `vendor-react` | react, react-dom | 56 KB |
| `vendor-motion` | framer-motion | 39 KB |
| `vendor-radix` | @radix-ui/* (27개) | 28 KB |
| `vendor-router` | react-router-dom | 14 KB |
| `vendor-icons` | lucide-react | 12 KB |
| `vendor-query` | @tanstack/react-query | 8 KB |

rolldown-vite (v7) 에서는 `manualChunks`를 **객체가 아닌 함수**로 작성해야 함:
```ts
manualChunks(id: string) {
  if (id.includes('node_modules')) {
    if (id.includes('framer-motion')) return 'vendor-motion';
    if (id.includes('@radix-ui'))    return 'vendor-radix';
    // ...
  }
}
```

> **트러블:** 처음 객체 형태로 작성했더니 `TypeError: manualChunks is not a function` 에러 발생.
> rolldown-vite(Vite 7)의 변경 사항 확인 후 함수 형태로 수정.

### 3. React Query 전역 캐시 전략

**적용 파일:** `src/lib/query-client.ts`

**변경 전:**
```ts
defaultOptions: {
  queries: {
    refetchOnWindowFocus: false,
    retry: 1,
  },
}
```

**변경 후:**
```ts
defaultOptions: {
  queries: {
    refetchOnWindowFocus: false,
    retry: 1,
    staleTime: 1000 * 60 * 5,   // 5분
    gcTime:   1000 * 60 * 30,   // 30분
  },
}
```

**각 옵션 의미:**

- `staleTime: 5분` — 데이터를 5분간 "신선한 상태"로 간주. 이 시간 안에 같은 queryKey로 useQuery가 다시 마운트되면 **API 재호출 없이 캐시 반환**. 숙소 목록, 동행 목록 등 자주 바뀌지 않는 데이터에 효과적.

- `gcTime: 30분` — 해당 쿼리를 사용하는 컴포넌트가 언마운트된 후에도 30분간 캐시를 메모리에 유지. 뒤로가기 시 API 재호출 없이 이전 데이터를 즉시 표시.

**주의:** 개별 `useQuery`에 명시적으로 `staleTime`이 설정된 경우 그 값이 전역 설정을 덮어씀 (기존 코드 유지).

### 4. 이미지 Lazy Loading

**적용:** 카드/목록 컴포넌트 내 `<img>` 태그에 `loading="lazy"` 속성 추가

**원리:**
`loading="lazy"`는 브라우저 네이티브 기능. 뷰포트에서 일정 거리 이내에 들어올 때 비로소 이미지를 요청함. JS 없이 작동하며 오버헤드 없음.

**적용 위치:**

|------|------------|
| `AccommodationReviewCard.jsx` | 리뷰 작성자 프로필 |

| `AdminMembers.jsx` | 회원 프로필 |

**적용 제외:**
- 히어로 배경 이미지 (Freeboards, Notices) — above the fold, 즉시 표시 필요
- 파일 업로드 미리보기 이미지 — 사용자가 방금 선택한 파일, 즉시 표시 필요

### 5. 미사용 패키지 제거 (recharts)

`package.json`에 `recharts`가 설치되어 있었으나 소스코드 어디에도 import 없음.
`npm uninstall recharts --legacy-peer-deps` 로 제거 → 의존성 38개 패키지 함께 제거.

> **참고:** `--legacy-peer-deps` 플래그 사용 이유 — `react-day-picker@8.x`가 `react@18`을 peer로 요구하는데 현재 프로젝트는 `react@19`를 사용 중. 기존부터 있던 충돌이므로 무시하고 진행.

## 올레길 기능 구현

---

### 기획 배경

HONDI는 제주 혼자 여행 커뮤니티를 표방하고 있지만, 정작 제주의 대표 콘텐츠인 **올레길** 정보가 없었다. 포트폴리오 관점에서 아쉬운 부분이었고, 백엔드 API 없이 정적 데이터만으로도 충분히 완성도 높은 기능을 만들 수 있다고 판단해 추가하기로 결정.

**선택 이유:**
- 올레길 26개 코스는 고정된 공공 정보 → DB 없이 정적 JSON으로 충분
- 카카오맵 폴리라인으로 경로 시각화 → 기존 KakaoMap 컴포넌트 확장 기회
- 난이도·지역 필터, 상세 페이지 구조 → 포트폴리오에서 "서비스 완결성" 어필 가능

### 1. 정적 데이터 설계 (`olleTrails.js`)

**코스 구성:** 메인 21개 코스 + 분기 코스 5개 (1-1, 7-1, 10-1, 14-1, 18-1) = **총 26개**

각 코스 객체의 스키마:

```js
{
  id: Number,           // 라우트 파라미터 (1~26)
  name: String,         // "1코스", "1-1코스" 등
  subtitle: String,     // "시흥초등학교 → 광치기해변"
  region: String,       // "제주시" | "서귀포시"
  distance: Number,     // km (소수점 1자리)
  difficulty: String,   // "하" | "중" | "상"
  duration: String,     // "4~5시간"
  terrain: String,      // "해안·오름" 등 복합 지형 설명
  description: String,  // 2~3줄 코스 소개
  startPoint: { name, lat, lng },
  endPoint:   { name, lat, lng },
  stamps: String[],     // 스탬프 포인트 이름 배열 (4~5개)
  path: { lat, lng }[], // 폴리라인 좌표 (5~9개 포인트)
}
```

**좌표 전략:**

제주 올레길 공식 GPS 트랙을 그대로 넣으면 포인트 수가 수백~수천 개가 된다. 지도 렌더 성능을 고려해 코스당 **5~9개 핵심 거점 좌표**만 사용하는 전략을 택했다. 실제 경로의 큰 방향감은 살리되, 세밀한 좌우 굴곡은 생략.

- 제주 동쪽 (성산): 33.46~33.47N, 126.88~126.93E
- 제주 남쪽 (서귀포): 33.24~33.26N, 126.54~126.61E
- 제주 서쪽 (한림/모슬포): 33.22~33.41N, 126.26~126.29E
- 제주 북쪽 (제주시): 33.50~33.54N, 126.52~126.64E
- 특이 코스: 우도(33.50N, 126.95E), 가파도(33.17N, 126.27E), 추자도(33.96N, 126.30E)

원형 코스(우도, 가파도, 추자도, 18-1)는 `path` 배열의 처음과 끝 좌표를 동일하게 설정해 폐합 경로를 표현.

### 2. KakaoMap 폴리라인 확장

**기존 `KakaoMap.jsx`의 구조:**
- `lat`, `lng`, `markers`, `panToMarker`, `onMapReady` prop 지원
- 단일 마커 / 다중 마커 두 가지 모드만 존재
- 폴리라인 기능 없음

**추가한 `path` prop:**

```js
// prop 추가
path,  // Array<{lat, lng}> — 폴리라인 좌표 배열

// buildMap() 내부, setStatus('ready') 직전에 삽입
if (path && path.length > 1) {
  const linePath = path.map(p => new window.kakao.maps.LatLng(p.lat, p.lng));
  const polyline = new window.kakao.maps.Polyline({
    path: linePath,
    strokeWeight: 4,
    strokeColor: '#0ea5e9',   // Tailwind sky-500
    strokeOpacity: 0.9,
    strokeStyle: 'solid',
  });
  polyline.setMap(map);
}
```

**설계 결정:**
- `path` prop이 없으면 기존 동작 그대로 (하위 호환 유지)
- 폴리라인은 마커와 독립적으로 동작 → 두 기능을 동시에 사용 가능
- 마커와 폴리라인을 모두 쓰면 출발·도착 마커 + 경로 선이 함께 표시됨

### 3. OlleTrails 목록 페이지

**구성:**

```
Header
└── Hero 섹션 (unsplash 제주 이미지, 총 코스 수·거리 뱃지)
└── sticky 필터 바
    ├── 난이도: 전체 / 하(emerald) / 중(amber) / 상(red)
    └── 지역:   전체 / 제주시 / 서귀포시 (teal)
└── 코스 카드 그리드 (3열 → 2열 → 1열 반응형)
Footer
```

**필터 구현:**

```js
const filtered = useMemo(() => {
  return olleTrails.filter((t) => {
    if (difficulty !== '전체' && t.difficulty !== difficulty) return false;
    if (region !== '전체' && t.region !== region) return false;
    return true;
  });
}, [difficulty, region]);
```

`useMemo`로 필터 결과를 메모이제이션. 26개 항목이라 체감 차이는 없지만, 렌더마다 재계산하지 않는 것이 올바른 패턴.

**카드 디자인 포인트:**
- 카드 상단에 teal→emerald 그라데이션 2px 컬러 배너 (페이지 전체 테마 강조)
- 코스 번호는 그라데이션 배지로 시각적 식별
- 난이도별 배지 색상: 하=emerald, 중=amber, 상=red (직관적 위험도 표현)
- `whileHover={{ y: -4 }}` framer-motion 애니메이션으로 카드 부상 효과
- `cardVariants`로 카드 순서대로 `delay: i * 0.04` 스태거 진입 효과

**필터 바 sticky:**
- `sticky top-0 z-20 bg-white/90 backdrop-blur-md` → 스크롤해도 항상 상단 고정
- Header가 `z-30` 이상이므로 z-index 충돌 없음

### 4. OlleDetail 상세 페이지

**구성:**

```
Header
└── 뒤로가기 버튼
└── 코스 헤더 카드 (이름, 지역 뱃지, subtitle)
└── 스탯 바 (4개 타일)
    ├── 거리 (sky)
    ├── 난이도 (난이도별 그라데이션)
    ├── 소요시간 (violet)
    └── 지형 (teal)
└── 카카오맵 카드
    └── KakaoMap (path + markers)
└── 코스 소개 카드
└── 스탬프 포인트 타임라인
Footer
```

**지도 중심 자동 계산:**

```js
const center = useMemo(() => {
  const lats = trail.path.map(p => p.lat);
  const lngs = trail.path.map(p => p.lng);
  return {
    lat: lats.reduce((a, b) => a + b, 0) / lats.length,
    lng: lngs.reduce((a, b) => a + b, 0) / lngs.length,
  };
}, [trail]);
```

경로 좌표의 산술 평균 → 폴리라인이 지도 중앙에 오도록 자동 배치. lat/lng를 직접 하드코딩하지 않아도 됨.

**줌 레벨 자동 계산:**

```js
const mapLevel = useMemo(() => {
  const span = Math.max(latSpan, lngSpan);
  if (span > 0.3) return 9;   // 추자도처럼 먼 섬
  if (span > 0.15) return 8;  // 장거리 코스 (4코스 등)
  if (span > 0.07) return 7;  // 중거리
  return 6;                   // 단거리
}, [trail]);
```

코스마다 경로 길이가 10~25km로 다양하므로 좌표 범위(span)를 보고 적절한 줌 레벨을 자동 결정. 고정값으로 쓰면 짧은 코스는 너무 확대되고, 긴 코스는 잘려서 보이는 문제가 생겼을 것.

**마커 구성:**

```js
const mapMarkers = useMemo(() => {
  const ms = [];
  ms.push({ ...trail.startPoint, name: `▶ 출발: ${trail.startPoint.name}` });
  // 순환 코스(출발=도착)는 도착 마커 생략
  if (trail.endPoint.lat !== trail.startPoint.lat || ...) {
    ms.push({ ...trail.endPoint, name: `■ 도착: ${trail.endPoint.name}` });
  }
  return ms;
}, [trail]);
```

우도·가파도·추자도 등 순환 코스는 출발점 = 도착점이므로 도착 마커를 따로 찍으면 같은 위치에 마커 2개가 겹침 → 좌표 비교로 중복 방지.

**스탬프 타임라인:**
- 인덱스 0: emerald (출발)
- 인덱스 마지막: red (도착)
- 중간: teal (경유)
- 각 포인트 사이에 `w-px h-8 bg-slate-100` 세로 구분선으로 타임라인 시각화
